Pipeline UFC: ¿seguir en la Mac o subir a la nube?

El problema real es el fin de semana con la laptop apagada: los trabajos (Hermes cron) hoy solo corren cuando la Mac está encendida. ¿Qué opciones hay y cuál conviene? Comparación anclada al proyecto raffleapp-dbc1b (hosting rifasmtz).

⚠ La clave que cambia el cálculo

Cuando un feed queda programado en Antwork, Antwork lo publica remotamente aunque la Mac esté apagada. La laptop solo se necesita para (a) ejecutar la recopilación y el render y (b) programar los feeds con antelación. Por eso el requisito de "fin de semana off" no exige mover TODO a la nube: exige que el trabajo de recopilar/render y de programar se haga antes del viernes y no dependa de la laptop encendida ese fin de semana.

Recomendación para el requisito "fin de semana off"

Hoy · sin migrar

Correr los trabajos antes del viernes

Antwork ya programa el feed remotamente y publica solo. Ajusta el cron para que el render de historias de sábado/domingo se prepare el viernes y se entregue a Telegram para revisión; el sábado lo publicas manual desde el teléfono. Cero costo, cero dependencia del fin de semana.

Cuando importe la fiabilidad

Cloud Scheduler → Cloud Run job

Costo ≈ $0 dentro del free tier. Es la vía nativa de Firebase sin tocar el "nunca push". Requiere Dockerizar el render con Chrome; es la opción más alineada si quieres desentenderte de "¿está encendida la Mac?".

Alternativa simple

VPS de $6/mes

Mismo código, mismo cron, en una VM 24/7. Más fácil de iterar que Cloud Run (SSH directo) y no te obliga a push público. Ideal si también quieres correr cosas sin acoplamiento a Google.

Descartada hoy

GitHub Actions

Funcional y gratis, pero exige subir el repo a GitHub, lo que contradice tu regla "local-only, nunca push". Solo la consideraría si relajas esa regla.

Qué hacer hoy (paso a paso)

  1. Ajustar el cron: mover el paquete del fin de semana al viernes (preparar Sáb+Dom el viernes) para que el sábado solo publiques desde el teléfono; sin slots perdidos ni capturas de la laptop.
  2. Revisar/desbloquear el health-check que hoy falla (falta automation.example.json) para tener una señal clara de salud.
  3. Decidir el umbral: si la Mac apagada en fin de semana es un caso raro, el paso 1 basta y vas a $0. Si quieres dormir tranquilo sin revisar, evaluar Cloud Run job (B) o el VPS (D) como segunda fase.
  4. Prototipar en paralelo: Dockerfile de prueba con Node 22 + Chrome para validar que el render corre en Cloud Run antes de comprometerte.
Decisión basada en: proyecto Firebase raffleapp-dbc1b / hosting rifasmtz, runner local (gather Mon/Wed/Fri 10:30; pack diario; sábado 07:00), Antwork como programador remoto, y precios públicos de Cloud Scheduler (3 jobs/mes gratis), Cloud Run (free tier vCPU/GiB) y DigitalOcean (droplet desde $4/mes).
